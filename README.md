# Кварта — лендинг ремесленной обжарки (Минск)

Тестовое задание. Клиент вымышленный. Next.js 15 (App Router) · TypeScript · Tailwind 4 · Zod.

**Сайт:** _ссылка после деплоя_ · **Lighthouse (mobile):** _приложить замер_

## Запуск

```bash
npm install
cp .env.example .env.local   # всё необязательно
npm run dev                  # http://localhost:3000
npm test                     # 35 тестов логики: телефон, дубли, хранилище, схема, неделя
```

Переменные (`.env.example`): `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` (хранилище на Vercel), `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` (дубль заявки в бот). Без них заявки пишутся в `.data/leads.jsonl`, Telegram пропускается.

## Решения

- **Хранилище — Upstash Redis по REST (`fetch`, без SDK).** На Vercel нет постоянной файловой системы, файл или SQLite потеряли бы заявки при следующем запуске функции. Redis даёт атомарную защиту от дублей: `SET dedup:<телефон> NX EX 600` либо ставит ключ, либо отвечает «уже есть», даже если запросы пришли на разные инстансы. Заявки лежат в списке `kvarta:leads`. Локально, без Redis, работает файл JSONL.
- **Дубли:** на сервере по номеру в формате E.164 на 10 минут (повтор отвечает `success: true`, «Заявка уже обрабатывается менеджером», в базу и Telegram не идёт); на клиенте кнопка блокируется через `ref` (state обновляется асинхронно и пропускает быстрый второй клик).
- **Источник заявки:** при входе `utm_*`, `yclid`, `fbclid`, `gclid`, `referrer` и страница входа сохраняются в `sessionStorage` и уходят в `/api/lead`. Новая рекламная ссылка в той же вкладке обновляет метки.
- **Telegram** отправляется через `after()` уже после ответа клиенту; его сбой заявку не ломает.
- **Дизайн «Обжарка»:** страница прожаривается по мере прокрутки. Секции — плоские поля цвета реальных стадий зерна: зелёное (герой), соломенное (история), светлая обжарка (каталог), средняя (подписка), тёмная (доставка и форма). В герое зерно в «барабане» за 14 секунд проходит все стадии, на первом треске раздувается и роняет шелуху, рядом подсвечивается название стадии. Анимация целиком на CSS (`@property` для цвета зерна), без JS; при `prefers-reduced-motion` остаётся статичное зерно. Остальная страница не анимируется: выразительность потрачена в одном месте. Запреты из брифа сохранены: без градиентов, размытых теней и скруглений больше 2px.
- **Шрифты:** Oswald (плотный узкий, как трафаретная печать на мешках с зелёным кофе) для заголовков и цифр, Literata для текста. Моноширинный шрифт убран: на один файл меньше.
- **Скорость:** ни одной растровой картинки на странице и ни одного стороннего скрипта: зёрна, шкала и бирки — inline SVG и CSS. Шрифты через `next/font`. При появлении фото от клиента — `next/image`.

## Где ИИ ошибся или был банален

- **Первый дизайн был шаблонным.** Кремовый фон, антиква, терракотовый акцент, подписи капсом моноширинным шрифтом, нумерация «01 —», стрелки на кнопках — это как раз набор, по которому узнаётся сгенерированная страница, хотя формально палитра и запреты из брифа были соблюдены. По просьбе переделать ушёл от него к идее «обжарка»; нумерация осталась только там, где есть настоящая последовательность (ритм недели).
- Промпт предлагал **Fraunces** для заголовков; насколько я знаю, у него на Google Fonts нет кириллицы, поэтому сначала я взял Alegreya, а в новой версии — Oswald и Literata. Что у обоих есть кириллица, подтвердит только сборка: проверить это в моей среде не удалось.
- Палитру из промпта и мою новую я проверял расчётом контраста по WCAG, и ни одна не прошла с первого раза. У исходной серый `#78716C` давал 4.36:1, а терракота на песочной плашке 4.25:1. В новой не прошли янтарный на зелёном (3.83:1), приглушённый светлый на зелёном (4.34:1) и красный штамп на корице (2.33:1). Значения подкрутил, а красный на корице заменил тёмным текстом. Теперь все пары «текст на поле» не ниже 4.5:1 (тёмный текст и карамельные кнопки — заметно выше).
- Классическая ловушка масок: если стирать символ маски (`)`, `-`), цифры не меняются, и маска «возвращает» символ, так что номер не стереть. Обработано заранее в `onPhoneChange`, но **в браузере не проверялось**. Номера вида `8 029…` разбираются только когда введены целиком, иначе первая цифра сбивала бы маску при наборе (покрыто тестами).
- В промпте для лотов были «обработка» и «высота», которых нет в ТЗ. Подставлены типичные для региона значения, помечены `ДОПУЩЕНИЕ` в `lib/catalog.ts`. Тексты истории тоже авторские: из ТЗ только 2019 год, бариста, 5 кг, четверг и пятница.

## Не проверено и что сделал бы иначе

- Скриншоты десктопа и мобильного вида снимал в Chromium через собственный стенд (серверный рендер компонентов + сборка Tailwind), но **со шрифтами-заменителями DejaVu**, которые заметно шире Oswald: с настоящими шрифтами заголовки будут короче. Кадры анимации проверял по моментам цикла; плавность и нагрузку на слабых телефонах не мерил, а текст бирки и успех формы после отправки в живом браузере не гонял.
- `next build`, Lighthouse и деплой на Vercel **не запускались** (в среде разработки не было доступа к npm): _после запуска вписать результат и найденные ошибки_.
- Нет e2e-теста формы и ограничения частоты запросов (только honeypot и дедупликация). Нет страницы просмотра заявок: смотрю в Upstash (`LRANGE kvarta:leads 0 50`) или Telegram.
