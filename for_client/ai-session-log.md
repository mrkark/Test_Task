# Лог взаимодействия с AI (Claude Code) — Проект «Кварта»

> Данный документ отражает реальный процесс проектирования, генерации кода, отладки и рефакторинга лендинга ремесленной обжарки кофе «Кварта» с использованием Claude Code.

## 1. Начальный бриф и концептуальные ограничения (Negative Constraints)

### Промпт разработчика:
```text
Разрабатываем лендинг для микро-обжарочной «Кварта» (Минск) на Next.js 15 (App Router).
Бриф: обжаривают раз в неделю по четвергам на ростере 5 кг, свежесть 1–3 дня, развоз по пятницам.
Сорта: Эфиопия Иргачеффе (32 BYN), Колумбия Уила (29 BYN), Бразилия Серрадо (26 BYN), Дрипы (18 BYN), Подписка (54 BYN).
Самовывоз: Минск, ул. Короля, 9.

ЖЕСТКИЕ ТРЕБОВАНИЯ К ДИЗАЙНУ (Negative Constraints):
1. Никакого шаблонного ИИ-глянца: запрещены фиолетово-синие неоновые градиенты, полупрозрачные стеклянные карточки (backdrop-blur), скругления rounded-2xl/3xl, одинаковые стрелочки на кнопках.
2. Сайт должен выглядеть как авторская работа студии для конкретной обжарочной.
3. Цветовая палитра должна отражать реальные стадии обжарки зерна (зеленое -> соломенное -> корица -> темное).
4. Вместо стандартных звездочек в отзывах сделай профессиональный скоринг кофейными зёрнами («Наша оценка»).
5. Валидация телефонов: только реальные белорусские коды (25, 29, 33, 44, 17), E.164.
6. Дедупликация 10 минут: повторный клик или отправка того же номера не создает дубль.
7. UTM-метки должны сохраняться в сессии и передаваться в заявку.
```

## 2. Ключевые технические итерации и исправление ошибок ИИ

### Сессия 1: Архитектура хранилища и Serverless
* **Запрос:** *«Почему на Vercel нельзя просто писать в локальный файл `leads.json`?»*
* **Ответ ИИ:** ИИ изначально предложил сохранять заявки в обычный локальный файл.
* **Вмешательство разработчика:** Указано, что Vercel использует Serverless-функции с эфемерной файловой системой — при перезапуске инстанса данные из файла сотрутся.
* **Решение:** 
  - Для облака (Vercel) настроена интеграция с Upstash Redis по REST API (`fetch`).
  - Для локальной разработки и тестирования без внешних сервисов реализовано сохранение в локальный `leads.json` с mutex-очередью (`fileLock`) для предотвращения состояния гонки.

### Сессия 2: Ошибка сборки Webpack на Windows
* **Проблема:** При вызове `npm run build` Next.js падал с ошибкой:
  `glob error EACCES: permission denied, scandir 'C:\Users\user\AppData\Local\Temp\dbus-...'`
* **Анализ:** Webpack кэшировал данные в системную папку `%TEMP%`, где находились защищенные сокеты подсистемы WSL/D-Bus.
* **Решение:** Переопределение временной директории на локальную папку:
  `$env:TEMP = ".temp"; $env:TMP = ".temp"; npm run build`.

### Сессия 3: Оптимизация производительности Lighthouse Mobile
* **Проблема:** Первичный замер на dev-сервере дал Performance 59 из-за компиляции на лету, тяжелого JS и блокировки веб-шрифтов.
* **Действия:**
  - Переход на продакшн-билд `npm run build && npm run start`.
  - Оптимизация SVG-путей барабана и зёрен.
  - Перевод анимации на чистый CSS `@property` и композитные свойства (`transform`, `opacity`), не триггерящие `reflow`.
* **Результат:** 
  - Accessibility: **100**
  - Best Practices: **100**
  - SEO: **100**
  - Performance: **88** (на Vercel с HTTP/2 и CDN — **93+**).

### Сессия 4: Телеграм-бот и безопасность данных
* **Запрос:** *«Нужен Telegram-бот для уведомления менеджеров, но как защитить данные клиентов от посторонних?»*
* **Решение:** 
  - Реализован принцип Fail-Closed: бот отвечает на команды (`/stats`, `/stop`, `/restart`) только авторизованным пользователям из `TELEGRAM_ALLOWED_CHAT_IDS`.
  - Поддержаны два режима: Webhook для продакшена на Vercel (`/api/telegram`) и Long-Polling (`scripts/telegram-poll.mjs`) для локальной разработки.

### Сессия 5: Адаптивность и мобильные скриншоты
* **Проблема:** На мобильных скриншотах при фиксированном окне 390 px обрезались правые края элементов (кнопки, заголовок).
* **Решение:** Написан скрипт автоматизации через Chrome DevTools Protocol (CDP) с эмуляцией экрана iPhone (390×844 px, touch: true). Сняты честные полноразмерные скриншоты (Full Scroll 390×9536 px) без обрезки интерфейса.
