> **Живой сайт на Vercel:** [https://kvarta-claude.vercel.app/](https://kvarta-claude.vercel.app/)  
> **Репозиторий проекта:** [https://github.com/mrkark/Test_Task](https://github.com/mrkark/Test_Task) (ветка реализации: `kvarta_claude`)  
> **Стек:** Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4, Zod, Upstash Redis / JSON, Telegram Bot API.

### 1. Что делали сами, а что делал ИИ
* **Делал ИИ (Claude Code):** первичная генерация компонентов по ТЗ, верстка адаптивной сетки на Tailwind CSS, написание unit-тестов (56 тестов), базовая логика эндпоинта `/api/lead` и скрипты настройки Telegram-вебхука.
* **Делали сами (архитектура и контроль):**
  - Сформулировали жесткие дизайн-ограничения (*Negative Constraints*), чтобы сайт не выглядел типовой нейросетевой поделкой: запретили фиолетовые градиенты, полупрозрачные стеклянные карточки (`backdrop-blur`) и скругления `rounded-2xl`.
  - Придумали визуальную концепцию стадий обжарки кофе (зеленое → сушка → корица → темная обжарка) и шкалу оценки сортов фирменными зёрнами вместо шаблонных отзывов со звёздочками.
  - Настроили часовой пояс Минска (`Europe/Minsk`) для корректного расчёта ритма недели обжарки и статистики заказов.
  - Спроектировали двухуровневую дедупликацию (оперативная память + проверка файла/Redis) и блокировку двойного клика через React `useRef`.

### 2. Где ИИ ошибся и как мы это заметили
1. **Эфемерная файловая система Vercel:** ИИ изначально предложил сохранять заявки только в локальный файл. При деплое на Vercel такой подход привел бы к потере данных при каждом перезапуске инстанса. Ошибку сразу пресекли и разделили логику: в облаке используется Upstash Redis по REST API, а локально — `leads.json`.
2. **Падение сборки Next.js в Windows:** Сборка `npm run build` падала из-за системных сокетов в папке `%TEMP%`. Мы диагностировали проблему и перенаправили временную директорию сборщика в локальную папку проекта.
3. **Ошибки верстки и обрезка на мобильных экранах:** При генерации первых скриншотов в десктопном окне 390 px обрезались правые края кнопок. Мы заметили это, написали скрипт с мобильной эмуляцией iPhone и добились идеальной адаптивности без горизонтального скролла.
4. **Безопасность Telegram-бота:** ИИ сделал обработчик команд общедоступным. Мы настояли на архитектуре *Fail-Closed* с авторизацией по белому списку chat ID (`TELEGRAM_ALLOWED_CHAT_IDS`), чтобы закрыть доступ к номерам клиентов посторонним лицам.

---

### 3. Почему для локального хранения выбран формат JSON
1. **Идеально под реальный масштаб:** «Кварта» — небольшая мастерская (ростер 5 кг, обжарка раз в неделю по четвергам, 5–30 заказов в неделю). Подключать ради десятка заявок тяжелую базу данных вроде PostgreSQL или MongoDB было бы ненужным усложнением на пустом месте.
2. **Работает сразу из коробки:** Проект можно клонировать и запустить за одну минуту без установки сторонних СУБД, Docker-контейнеров и настройки прав доступа.
3. **Понятно человеку:** Файл `leads.json` можно открыть в обычном Блокноте, сразу увидеть телефон и комментарий клиента, переслать менеджеру или скопировать в Excel / Google Таблицы.
4. **Надежность:** Запись в файл защищена очередью, поэтому данные не перемешаются при одновременных заказах, а повторные заявки с одного номера отсекаются в течение 10 минут.
